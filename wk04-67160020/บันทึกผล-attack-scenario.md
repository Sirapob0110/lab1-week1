# บันทึกผลการทดสอบ Attack Scenario

## 1. Payload ขนาดใหญ่ผิดปกติ

ได้ทดสอบส่งคำขอ POST /api/v1/students โดยส่งค่า name ที่มีความยาวประมาณ 15,000 ตัวอักษร ทำให้ request body มีขนาดเกินขีดจำกัด 10KB ที่กำหนดไว้ใน express.json()

ผลการทดสอบพบว่าเซิร์ฟเวอร์ปฏิเสธคำขอและตอบกลับด้วย Status Code 413 Payload Too Large แสดงว่าการจำกัดขนาด JSON body สามารถช่วยป้องกันคำขอที่มี payload ขนาดใหญ่ผิดปกติได้ในระดับหนึ่ง

ข้อสังเกต: การกำหนด limit ช่วยป้องกันไม่ให้เซิร์ฟเวอร์ต้องรับและประมวลผลข้อมูลขนาดใหญ่เกินความจำเป็น ซึ่งช่วยลดความเสี่ยงจากการส่ง request ที่มีขนาดผิดปกติ

## 2. Type Confusion

ได้ทดสอบส่งค่า name เป็น object แทนที่จะเป็น string ดังนี้

{
"name": {
"malicious": "payload"
},
"major": "วิทยาการคอมพิวเตอร์",
"email": "test2@example.com"
}

ผลการทดสอบพบว่าระบบสามารถรับข้อมูลดังกล่าวได้ เนื่องจาก validation ในปัจจุบันตรวจสอบเพียงว่าฟิลด์ name มีค่าหรือไม่ แต่ยังไม่ได้ตรวจสอบชนิดข้อมูลว่า name ต้องเป็น string

ข้อสังเกต: แสดงให้เห็นว่าการตรวจสอบเพียงการมีค่าของข้อมูลยังไม่เพียงพอ เพราะผู้ใช้สามารถส่งข้อมูลผิดประเภทเข้ามาได้ การแก้ไขปัญหานี้ควรมีการตรวจสอบ schema และชนิดข้อมูลของแต่ละ field อย่างชัดเจน ซึ่งใน Lab นี้ยังไม่ได้แก้ไข Type Confusion เนื่องจากเป็นประเด็นที่กำหนดให้สังเกตและจะมีการใช้ Zod เพื่อจัดการ validation ในเนื้อหาต่อไป
