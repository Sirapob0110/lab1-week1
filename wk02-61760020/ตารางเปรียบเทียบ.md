# ตารางสรุปผลการเปรียบเทียบ REST และ GraphQL

## ผลการทดลองจริง (บันทึกจาก Postman)

| หัวข้อเปรียบเทียบ                                    | REST (`/students/1/full`)                                | GraphQL                                                              |
| ----------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------- |
| จำนวนคำขอที่ใช้เพื่อดูชื่อและรายวิชาของนักศึกษา 1 คน | 1 คำขอ (แต่ได้ฟิลด์เกินความจำเป็น)                        | 1 คำขอ (ได้เฉพาะฟิลด์ที่ต้องการ)                                       |
| จำนวนคำขอที่ใช้เพื่อดูชื่อและรายวิชาของนักศึกษาทุกคน | มากกว่า 1 คำขอ หากต้องแยกดึงข้อมูลรายวิชาทีละ endpoint    | 1 คำขอ                                                                  |
| ขนาด response body (จริงจาก Postman)                  | 671 B                                                       | 461 B (query เฉพาะฟิลด์) / 758 B (query ทุกคนพร้อมรายวิชา)             |
| ฟิลด์ที่ได้รับเกินความจำเป็น (over-fetching)         | มี เช่น `email`, `phone`, `courseIds`                     | ไม่มี — ผู้เรียกกำหนดฟิลด์ที่ต้องการเองในคำขอ                          |

## รายละเอียดคำขอที่ทดสอบ

1. **REST** — `GET http://localhost:3000/api/v1/students/1/full`
   → ได้ข้อมูลครบทุกฟิลด์ของนักศึกษา (รวม `email`, `phone`, `courseIds` ที่ไม่จำเป็นสำหรับหน้าจอที่ต้องการแค่ชื่อกับรายวิชา) ขนาด 671 B

2. **GraphQL (เฉพาะฟิลด์ที่ต้องการ)** —
   ```graphql
   query {
     student(id: 1) {
       name
       courses {
         courseName
       }
     }
   }
   ```
   → ได้เฉพาะ `name` และ `courseName` เท่านั้น ไม่มีฟิลด์อื่นติดมา ขนาด 461 B (เล็กกว่า REST อยู่ 210 B)

3. **GraphQL (ทุกคนในคำขอเดียว)** —
   ```graphql
   query {
     students {
       name
       major
       courses {
         courseName
         credit
       }
     }
   }
   ```
   → ได้ข้อมูลนักศึกษาทุกคนพร้อมรายวิชาครบถ้วนในคำขอเดียว (ขนาด 758 B) เทียบกับ REST ที่ต้องเรียกหลาย endpoint แยกกันหากต้องการข้อมูลชุดเดียวกัน

## สรุป

จากผลการทดลองจริง พบว่า GraphQL แก้ปัญหา **over-fetching** ได้ชัดเจน เพราะ response มีขนาดเล็กลง (461 B เทียบกับ 671 B ของ REST) เนื่องจากผู้เรียกกำหนดฟิลด์ที่ต้องการเองตั้งแต่ต้น และแก้ปัญหา **under-fetching** ได้เช่นกัน เพราะสามารถดึงข้อมูลนักศึกษาทุกคนพร้อมรายวิชาที่ลงทะเบียนได้ในคำขอเดียว โดยไม่ต้องเรียกหลาย endpoint แยกกันเหมือนฝั่ง REST
